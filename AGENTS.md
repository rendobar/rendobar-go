# Working in rendobar-go

For coding agents changing this SDK. Users of the SDK want the README.

- `internal/api/` is generated by Fern from `fern/openapi.json` (the published spec). Never edit it.
  Regenerate: `cd fern && fern generate --local --group go --force`, then delete `internal/api/go.mod`,
  `go.sum`, `README.md`, `CONTRIBUTING.md` and `reference.md` (the regenerate workflow does this).
- `fern/generators.yml` filters generation to the endpoints the root package calls (`settings.filter.endpoints`).
  A new public method needs its endpoint added there and a regeneration. `POST /billing/checkout/pro` is
  listed only because conformance scenario C14 needs a deprecated route.
- `spec_gen.go` and `webhooks/events_gen.go` are generated by `internal/cmd/genparams` from
  `fern/openapi.json` (`go generate ./...`). `spec_gen.go` has one params struct per job type, enum types
  with constants, sealed union interfaces, `Validate` methods, the response enums and the ffprobe result
  types. `events_gen.go` has the event names, one data type per webhook event and `Event.Payload`.
  Never edit them. CI fails when they are stale, and the regenerate workflow runs `go generate` after
  Fern. A union whose branch names read badly gets a name in `branchNames`. A response enum that is a type
  the SDK already has gets an entry in the webhooks `aliases`.
- Param type rules are frozen, so a harmless schema change never breaks a Go caller: every integer is
  `int64`, every number `float64`; integer, number, boolean and object fields are always pointers,
  required or not; strings and enums are always values; unions are interfaces; every tag has
  `omitempty`. Required-ness lives only in `Validate`. `internal/cmd/genparams/rules_test.go` pins the
  rules and a golden file (`go test ./internal/cmd/genparams -update` after a reviewed change).
- Job and account reads (`rawjson.go`) and `Jobs.Download` bypass the core. The core decodes integers
  into `int`, which overflows on 32-bit platforms. CI runs the tests as `GOARCH=386`.
- The job model (`job.go`) stays hand-written on purpose: it turns the wire's Unix-ms integers and
  millisecond counts into `time.Time` and `time.Duration`, and models statuses as variants. Its enums
  and the shapes it does not convert come from the spec.
- Hand-written code is the root package (`client.go`, `jobs.go`, `job.go`, `params.go`, `probe.go`, `download.go`, `types.go`, `errors.go`, `retry.go`, the tests) and `webhooks/`.
- Retries belong to `retry.go`, not the core (the core runs with `option.WithoutRetries`): 429, 500, 502,
  503, 504 and connection errors only, honouring `Retry-After` up to 60 s. The core's own retrier would also retry 408.
- Behaviour follows the cross-SDK standard that the shared conformance scenarios encode. C19 to C39 live
  in `parity_test.go` and skip, loudly, against a mock without `/__requests`. `RENDOBAR_CONFORMANCE_REQUIRE=1`
  turns each skip into a failure. CI sets it to 0 until rendobar/openapi PR #2 merges, then flips it to 1.
- Errors have one idiom: `errors.As` to `*Error` and compare `Code` with the `Code...` constants. No `Is*` helpers.
- `Jobs.Download` streams through `download.go`, not the core, which buffers bodies. Its endpoint is
  not in the Fern filter.
- Users never import `internal/api`, and no generated type is part of the public API. The root package
  defines its own types (`job.go`, `types.go`) and builds them from the JSON of the core's responses, so
  a regeneration cannot change the public API. A new spec field users need is added there by hand.
  `job_test.go` pins the wire names, so a renamed field fails a test instead of reading as zero.
- Method names match `@rendobar/sdk` and the Python SDK (`Jobs.Create/Get/List/All/Wait/Run/Cancel/Download/Types/Schema`).
- Behaviour is defined by the shared conformance scenarios (`conformance_test.go`). Every id must pass.
- Webhook verification must agree with `webhooks/testdata/webhook-vectors.json`.
- Breaking changes are caught in two layers. `apidiff` (CI, against the last release tag)
  covers the hand-written root package and `webhooks/`, every public type included. It
  ignores `internal/`: the core only changes when the spec does, and the API's deploy gate
  (oasdiff) blocks a breaking spec change before it is live.
- `fern/` ships in the module because the regenerate workflow and the CI mock read `fern/openapi.json`.

- `examples/` is its own module with a `replace` to the root, so `go test ./...` at the root skips it.
  Every example must pass `examples/run.sh --mode mock` (CI job `examples`) and stay free of `any`
  and casts. A step the mock cannot answer prints `SKIP (mock: <why>)`. `examples-live.yml` runs
  them against staging, seven billed jobs per run, so keep new live steps to short clips.

Checks: `go vet ./...`, `go test ./...` with the conformance mock on `RENDOBAR_MOCK`, serving
`fern/openapi.json` as CI does.
