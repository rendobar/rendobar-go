# Working in rendobar-go

For coding agents changing this SDK. Users of the SDK want the README.

- `internal/api/` is generated by Fern from `fern/openapi.json` (the published spec). Never edit it.
  Regenerate: `cd fern && fern generate --local --group go --force`, then delete `internal/api/go.mod`,
  `go.sum`, `README.md`, `CONTRIBUTING.md` and `reference.md` (the regenerate workflow does this).
- Hand-written code is the root package (`client.go`, `jobs.go`, `errors.go`, `retry.go`, the tests) and `webhooks/`.
- Retries belong to `retry.go`, not the core (the core runs with `option.WithoutRetries`): 429, 5xx and
  connection errors only, honouring `Retry-After`. The core's own retrier would also retry 408.
  Users never import `internal/api`; the root package re-exports what they need as type aliases.
- Method names match `@rendobar/sdk` and the Python SDK (`Jobs.Create/Get/List/All/Wait/Run/Cancel/Download/Types/Schema`).
- Behaviour is defined by the shared conformance scenarios (`conformance_test.go`). Every id must pass.
- Webhook verification must agree with `webhooks/testdata/webhook-vectors.json`.
- Breaking changes are caught in two layers. `apidiff` (CI, against the last release tag)
  covers the hand-written root package and `webhooks/`. It ignores `internal/`, so the
  generated types behind the aliases (`Job`, `JobType`, ...) are not compared there:
  those only change when the spec does, and the API's deploy gate (oasdiff) blocks a
  breaking spec change before it is live.

Checks: `go vet ./...`, `go test ./...` with the conformance mock on `RENDOBAR_MOCK`, serving
`fern/openapi.json` as CI does.
